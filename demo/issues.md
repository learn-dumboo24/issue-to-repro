## Issue 1

**Title:** Amounts of ₹1 lakh and above use international grouping instead of lakh/crore

**Body:**

`format_inr` says it uses Indian digit grouping, but anything from one lakh up comes out with
groups of three, like a US amount.

```python
from splitbill import format_inr

print(format_inr(12345650))    # ₹123,456.50
print(format_inr(1234567800))  # ₹12,345,678.00
```

Expected `₹1,23,456.50` and `₹1,23,45,678.00`. Amounts under ₹1,000 look fine. We show these
totals to users in India, so `₹123,456.50` reads as wrong to them.

splitbill 0.3.0, Python 3.12

## Issue 2

**Title:** Splitting ₹100 between 3 people only adds up to ₹99.99

**Body:**

The docstring for `split_equally` says the shares always add up to the total, but they don't when
the amount doesn't divide evenly:

```python
from splitbill import split_equally

shares = split_equally(10000, ["Asha", "Ravi", "Meera"])   # ₹100.00
print(shares)                 # {'Asha': 3333, 'Ravi': 3333, 'Meera': 3333}
print(sum(shares.values()))   # 9999
```

One paisa disappears, so our app's "settle up" screen never reaches exactly zero. Somebody should
pay the extra paisa. `split_by_shares` already handles this correctly.

## Issue 3

**Title:** "12.5" is parsed as ₹12.05 instead of ₹12.50

**Body:**

Users often type amounts with one decimal place. `parse_amount` reads them as paise:

```python
from splitbill import parse_amount

parse_amount("12.50")  # 1250 (correct)
parse_amount("12.5")   # 1205 (expected 1250)
```

So a ₹12.50 coffee gets recorded as ₹12.05. Two decimal places work fine.

## Issue 4

**Title:** Settle up says "Meera pays Meera ₹0.00" when someone is already even

**Body:**

If one person in the group has a zero balance, `settle_up` adds a payment from them to themselves:

```python
from splitbill import settle_up

print(settle_up({"Asha": 5000, "Ravi": -5000, "Meera": 0}))
# [('Ravi', 'Asha', 5000), ('Meera', 'Meera', 0)]
```

Expected just `[('Ravi', 'Asha', 5000)]`. Our app shows the extra line as "Meera pays Meera
₹0.00", which confuses people.

## Issue 5

**Title:** Feature request: split by percentage

**Body:**

It would be great to split a bill by percentages, e.g. 50% / 30% / 20%, instead of whole-number
shares. Something like:

```python
split_by_percent(10000, {"Asha": 50, "Ravi": 30, "Meera": 20})
```

It should still add up to the total exactly, like `split_by_shares` does.
